# AFE — setup guide

[Português (BR)](../../LEIA.md) · **English**

> The editor's interface is in Portuguese. In these docs, button and field names appear exactly as on screen,
> followed by a translation the first time — e.g. **✎ Editar** (Edit).

A visual editor for artwork made in HTML (posts, carousels, stories, banners): you open the art in the browser
and adjust it **with the mouse**, without touching its code — move, resize and retype, glows and shadows,
corners and outlines, add images and shapes, animate with keyframes and render the video.

This folder is **complete and self-contained**: it doesn't depend on any project. To use it with another
project or client, just copy it (see "Taking it to another project").

## How it works, in one sentence

The editor **never changes the art's code**: it saves your changes in a data file next to it
(`<art>.edicoes.js`), and a small library inside the art applies those changes every time the art opens —
in the editor, in the browser, or when rendering the PNG/video.

## Opening the editor

All commands run **from inside the AFE folder** (your artworks can live anywhere):

```bash
python servidor.py --raiz ART_FOLDER
```

Then open `http://localhost:8765/editor/` in the browser (Edge or Chrome). The field at the top lists the
`.html` artworks in the folder; the ones with ✓ are already connected to the editor.

- `--raiz` ("root") is the folder where the artworks live (it can have subfolders). `--porta 8765` changes the
  port.
- `--biblioteca Brand=IMAGE_FOLDER` ("library"; optional, can be repeated): a folder of images — a client's
  brand assets, for example — shown in the Assets tab of **every** artwork, organized by its subfolders.
  "Brand" is the name shown on screen; the folder can be anywhere.
  **Code components:** if next to the image folder (or inside it) there is a `components/` folder — an
  exported design system, with `components/<Name>/preview.html`, `README.md` and the brand's `.css` files —
  the components also appear in the Assets tab, ready to drop into the art.
- The server only answers this computer. It only writes each artwork's edits file and, when you use an image
  or a component from the library, copies (images and brand CSS) inside the artwork's folder
  (`assets/biblioteca/`).

Example with a library: `python servidor.py --raiz ../my-art --biblioteca Brand=../my-brand/assets`.

## Connecting an artwork to the editor

An artwork can only be edited after it is "connected" (once per artwork):

```bash
python ligar.py PATH/to/art.html
```

This copies the library next to the art, creates the empty edits file and adds two `<script>` lines to the
`.html`. There are two modes, chosen automatically:

- **automatic** — a regular artwork, which doesn't signal when it has finished building: done, just open it
  in the editor.
- **manual** — an artwork that builds itself with code and sets `data-pronto` ("ready"; generated by a
  script): `ligar.py` prints 2 lines to add to the art's code, before it sets `data-pronto`:

  ```js
  await EDLIB.preparar(N);   // new items + edited texts (BEFORE measuring text)
  // ...the art's own adjustments that measure text...
  EDLIB.finalizar(N);        // position, size, effects, shape, animation
  ```

`python ligar.py art.html --conferir` ("check") shows how the art is set up, without changing
anything. Running `ligar.py` again on a connected artwork only updates the copy of the library.

**What the art needs:** a fixed size (e.g. 1080×1350) and, preferably, one element that contains everything,
with `id="post"` (or the `data-ed-raiz` attribute). Optional: `window.CONFIG = { largura, altura, paginas }`
(width, height, pages) and `data-nome="..."` on elements to name the layers.

## Quick test (2 minutes)

```bash
python servidor.py --raiz exemplo
```

Open `http://localhost:8765/editor/?arquivo=exemplo.html`, click **✎ Editar** (Edit) and play
around: it's a sample artwork made for that.

To check that everything still works after changing the editor's code:

```bash
python testes/teste_rapido.py
```

It drives the real editor in a hidden browser (select, move, text, effects, shape, layers, assets, keyframes,
curves, copy/paste, layer timing, stagger, entrances, cover, save) and shows what passed. With `--video` it
also renders a test video.

## Taking it to another project or client

1. Copy the whole AFE folder anywhere (or download it from GitHub).
2. Connect the project's artworks: `python ligar.py path/art.html`.
3. Open it: `python servidor.py --raiz art-folder`.

To **edit**, all you need is Python 3 (the server only uses the standard library) and a browser (Edge or
Chrome). To **render video** you also need Playwright for Python and ffmpeg — the editor tells you if
something is missing, and never installs anything by itself. The automated test uses Playwright.

## Where your edits live

- In a file next to the art: `<art name>.edicoes.js` (in older artworks, `edicoes.js`).
- On every **Salvar** (Save), the previous version is kept in `build/edicoes-anteriores/` (or
  `.edicoes-anteriores/`, if the art's folder has no `build/`). You can delete it whenever you like.
- Deleting the edits file (or leaving it as `window.EDICOES = {};`) brings the art back to the original.
